# OS-599 — Cuota de aprendizaje SENA (estimación)

## Objetivo

Estimación interna de cumplimiento de la cuota de aprendices (Ley 789/2002) por tenant y período de nómina (`YYYY-MM`), para alimentar el dashboard de reportes.

**No sustituye** la cuota oficial fijada por la regional SENA ni el acto administrativo de monetización.

## Fase 1 — Motor de cálculo (implementado)

### Contrato de salida público — `SenaQuotaService.calculateForTenant()`

```ts
type SenaMonetizationRegime = 'LEY_789_2002' | 'LEY_2466_2025';

interface SenaQuotaResult {
  period: string; // YYYY-MM
  eligibleWorkers: number;
  requiredApprentices: number;
  activeApprentices: number;
  missingApprentices: number;
  smlv: number;
  monetizationRegime: SenaMonetizationRegime;
  estimatedMonetizationAmount: number;
  status: 'EXEMPT' | 'COMPLIANT' | 'PENDING';
  estimated: true;
}
```

| Campo                         | Notas                                                                                                                      |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `monetizationRegime`          | `LEY_789_2002` si `asOfDate < 2025-06-25T00:00:00.000Z`; `LEY_2466_2025` desde esa fecha inclusive.                        |
| `estimatedMonetizationAmount` | COP enteros según la fórmula del régimen.                                                                                  |
| ~~`monetizationFactor`~~      | **Eliminado** del resultado público. El `1.5` post-reforma es detalle interno (`SENA_CUOTA_MONETIZACION_FACTOR` / NOM-06). |

Ubicación de tipos: `apps/api/src/payroll/interfaces/sena-quota.interfaces.ts`.

### Contratos computables (denominador)

Única fuente de verdad: `SENA_QUOTA_ELIGIBLE_CONTRACT_TYPES` en `apps/api/src/payroll/payroll.constants.ts`.

| Incluidos    | Excluidos del denominador                                         |
| ------------ | ----------------------------------------------------------------- |
| `FIJO`       | `APRENDIZAJE` (solo cuentan en `activeApprentices`)               |
| `INDEFINIDO` | `PRESTACION` (prestación de servicios / independientes — art. 34) |
| `OBRA`       |                                                                   |

> En el schema Prisma el enum es `PRESTACION`, no `PRESTACION_SERVICIOS`.

Fuente histórica de tipo de contrato: `EmploymentContract` al cierre del período (`findContractsAsOfForTenant`). **No** usar `EmployeeDetails.contractType` como fuente principal.

### Cuota estimada (art. 33 Ley 789/2002)

- &lt; 15 trabajadores computables → `EXEMPT`, cuota 0
- 15–20 → 1 aprendiz
- &gt; 20 → `floor(n/20)` + 1 si remanente ≥ 10

Estados: `EXEMPT` | `COMPLIANT` | `PENDING`. Resultado siempre con `estimated: true`.

### Monetización — transición legal

| `monetizationRegime` | Vigencia (as-of cierre de período) | Fórmula                                                                             |
| -------------------- | ---------------------------------- | ----------------------------------------------------------------------------------- |
| `LEY_789_2002`       | `asOfDate < 2025-06-25`            | Total = `0.05 × eligibleWorkers × SMLMV`. Parcial = `(missing / required) × total`. |
| `LEY_2466_2025`      | `asOfDate ≥ 2025-06-25`            | `missingApprentices × SMLMV × factorInterno` (factor canónico **1.5**, no expuesto) |

**Fecha exacta de transición:** `2025-06-25T00:00:00.000Z` (`SENA_CUOTA_LEY_2466_EFFECTIVE_FROM`).

**Modelado interno:**

- Régimen histórico: fórmula en código (`sena-quota.calculation.ts`); **no** se modela como multiplicador NOM-06.
- Post-reforma: factor versionado NOM-06 key `SENA_CUOTA_MONETIZACION_FACTOR` (seed GLOBAL `1.5` desde `2025-06-25`).
- SMLV siempre vía `LaborLegalParametersService.getValueAt('SMLV', asOfDate, tenantId)`.

### Seed cleanup (vigencia incorrecta `1.0`)

El seed soft-deletea solo la fila GLOBAL `SENA_CUOTA_MONETIZACION_FACTOR` con `validFrom=2020-01-01` y `value=1` (aproximación OS-599 previa).

Validación por inspección (sin test de seed dedicado — el patrón de seeds del repo no cubre unit tests de cleanup):

1. **`getValueAt` ignora eliminados** — `LaborLegalParametersRepository.findActiveAt` filtra `deletedAt: null` (`labor-legal-parameters.repository.ts`).
2. **Idempotencia** — `updateMany` con `deletedAt: null`; re-ejecutar no altera filas ya soft-deleted. El upsert del `1.5` restaura `deletedAt: null` en la vigencia canónica.
3. **Sin duplicar `1.5`** — unique `tenantScope_key_validFrom` + upsert.
4. **Sin tocar overrides de tenant** — cleanup acotado a `tenantScope: GLOBAL`.
5. **Alcance mínimo** — where incluye `value: 1` y `validFrom` 2020-01-01; no afecta la vigencia `2025-06-25` / `1.5`.

### Limitaciones del carácter estimativo

- La cuota oficial la determina el SENA regional; este motor solo estima.
- Corte as-of fin de mes (UTC), no overlap parcial mid-period.
- No clasifica cargos/ocupaciones SENA ni excepciones sectoriales.
- No persiste cuota oficial ni pagos de monetización.

## Fase 2 — API REST + Postman (implementado)

### Endpoint definitivo

```http
GET /api/reports/sena-quota?period=YYYY-MM
```

**Decisión de ruta:** bajo `ReportsController` (mismo dominio que `GET /api/reports/payroll` / `social-security`), no embebido en el response de payroll.

### DTOs

| Archivo                                                          | Rol                                   |
| ---------------------------------------------------------------- | ------------------------------------- |
| `apps/api/src/reports/controller/dto/sena-quota-query.dto.ts`    | Query: `period` obligatorio `YYYY-MM` |
| `apps/api/src/reports/controller/dto/sena-quota-response.dto.ts` | Respuesta Swagger = contrato Fase 1   |

### Guards / permisos

- `@UseGuards(JwtAuthGuard, RolesGuard)`
- `@Roles(...PAYROLL_MODULE_ROLES)` — **mismo** acceso de lectura que reportes de nómina
- **No** se creó permiso nuevo
- `tenantId` desde JWT (fallback `x-tenant-id`); **nunca** desde query/body

### Contrato público HTTP

Idéntico a `SenaQuotaResult` (sin `monetizationFactor`). Swagger documenta carácter estimativo y que no sustituye la cuota oficial SENA.

## Fase 3 — Dashboard de cumplimiento SENA (implementado)

### Ubicación definitiva

Panel hermano de `PilaPeriodPanel` en:

`apps/web-app/src/features/payroll/screens/PayrollReportsScreen.tsx`

Componente: `SenaQuotaPanel` — título **Cumplimiento cuota SENA**, eyebrow **Estimación informativa**.

Consume el mismo `payrollPeriod` (`YYYY-MM`) del dashboard; se actualiza al cambiar las fechas.

### Cliente / hook

| Pieza                    | Ubicación                                                         |
| ------------------------ | ----------------------------------------------------------------- |
| Tipo `SenaQuotaResponse` | `types/payroll-reports.types.ts` (sin `monetizationFactor`)       |
| `getSenaQuota(period)`   | `api/payroll.client.ts` → `GET /reports/sena-quota`               |
| Query key                | `payrollKeys.senaQuota(period)`                                   |
| Hook                     | `useSenaQuotaQuery(period)` en `hooks/usePayrollReportQueries.ts` |

Sin GraphQL. Sin `tenantId` en query/body (headers de auth existentes).

### Mapeo visual de estados

| API         | Badge UI  | Tono                           |
| ----------- | --------- | ------------------------------ |
| `EXEMPT`    | Exento    | Neutro / informativo           |
| `COMPLIANT` | Cumple    | Positivo                       |
| `PENDING`   | Pendiente | Advertencia (no error crítico) |

No se muestra “Incumplimiento legal”. `monetizationRegime` no se expone como enum; si hay monetización > 0 se muestra texto legible del régimen.

### Monetización

- `estimatedMonetizationAmount > 0` → bloque “Valor estimado a monetizar” (COP).
- Valor `0` → no se muestra bloque ni `$0` como alerta.

### Loading / error

- Loading y error **aislados** en `SenaQuotaPanel` (no ocultan el dashboard ni PILA).
- Retry vía botón “Reintentar” + React Query (`retry: 1` global).
- `SenaQuotaPanel` y `PilaPeriodPanel` se montan siempre que exista `payrollPeriod` válido: **no** dependen de `payrollQuery.isSuccess` ni del early-return de carga/error del reporte principal. Si falla payroll, el error se muestra en el bloque del dashboard y SENA/PILA siguen consultando.

### Disclaimer (obligatorio)

> Esta estimación se basa en los contratos registrados en Restopsiq y no sustituye la cuota oficial determinada por el SENA.

El resultado **sigue siendo estimativo** (`estimated: true` en contrato).
