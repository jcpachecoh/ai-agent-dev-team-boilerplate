## Objetivo

Permitir que un **Administrador de sede** solicite de forma **proactiva** una extensión de jornada para uno o varios colaboradores, reutilizando el modelo y la cascada de aprobación de CONN-04a (`OvertimeRequest` / `OvertimeApproval`), sin reimplementar detección automática ni pantallas paralelas.

---

## Arquitectura final

```
Admin sede (cargo + UserLocation + attendance.overtime.request)
  POST /api/attendance/overtime-requests/administrative
       │
       ▼ OvertimeAdminCreateService (tx all-or-nothing)
  N × OvertimeRequest SOLICITUD_ADMINISTRATIVA
      status = PENDIENTE_GERENCIA_OPERACIONES
      batchId compartido (trazabilidad)
      workDate / proposed* / reasonOptionId / requestedByUserId
       │
       ▼ notifyLevelPending (Logger stub → Ops)
  Ops approve → PENDIENTE_GERENCIA_GENERAL
  Ops object  → OBJETADA (solo esa fila)
  GG approve  → APROBADA
  GG object   → OBJETADA
       │
       ▼ NOM-07 ReportsService.applyOvertimeApprovalGate
  liquidable = merge(autoAuth ∪ adminAuth) ∩ OVERTIME marcado
  pending-salary / variable-average: mismo motor + classifyOvertimeSurcharge
```

### Modelo y migración

- Migración: `20260716235900_os606_admin_overtime_request`
- Enum `EmployeeCatalogType.OVERTIME_REASON`
- Campos admin en `OvertimeRequest`; detection fields nullable
- Unique parciales SQL: auto por período; admin por ventana (`status <> OBJETADA`)

### Flujo de aprobación

- Admin **no** tiene nivel de approve (es solicitante).
- Cascada: Ops → GG.
- Objeción terminal por fila; hermanas del `batchId` intactas.
- Re-solicitud misma ventana tras `OBJETADA` permitida (unique excluye objetadas).

### Catálogo

- 3 motivos seed demo; CRUD `/payroll/catalogs` con `isActive` (sin hard delete).
- Escritura catálogo = roles nómina (`PAYROLL_WRITE_ROLES`), no `attendance.overtime.request`.
- Historial conserva label vía FK `reasonOptionId`.

### Reglas NOM-07

- Admin `APROBADA` autoriza ventana; paga intersección con pares `markingScope=OVERTIME`.
- Sin marcación → 0. Parcial → intersección. Auto+admin → unión sin doble conteo.
- Legacy CONN-04a: auto `APROBADA` sin pares OVERTIME → summary total−480.
- Tarifa por horario real (`classifyOvertimeSurcharge`); `type` ≠ tarifa (no 75% admin).

### Integración OS-551

- Tarjeta muestra origen (`DETECCION_AUTOMATICA` / `SOLICITUD_ADMINISTRATIVA`) y estado.

### Pending salary / variable average

- Util compartido `approved-overtime-money.util` (Task-09).
- Demo seed `APROBADA` sin marcación → dinero 0 (intencional).
